# Food usability review — 15 October 2026

Reviewed the existing private captures `35-before-food-correction-dialog.jpg` and `36-before-builder-usability.jpg`. No native screenshot was available for this review. These observations concern the captured interface; source checks and later device testing are separate evidence.

- The food correction dialog starts with weight and servings without first showing the food being edited. Show an editable food name and explain that changing the name alone does not replace its nutrition. Keep choosing a database match as a separate, explicit action.
- “Weight” and “Servings” look like independent amounts. Explain their relationship in plain language and show which amount the nutrient totals describe.
- The meal builder places food search, additional entry actions and portion controls before the existing food list. Bring the foods already in the meal into view before optional ways to add more.
- Use a visible “Edit food” action for each food. A pencil icon alone makes the main correction task harder to discover.
- Keep an editable suggested meal name, with the meal category and time nearby. Preserve a name the person has entered.
- Put the selected portion and one main six-nutrient summary together. Repeated summaries make it harder to identify the amount that will be saved.

The captured category and entry buttons already use consistent rectangular outlines. Preserve that treatment while improving the order and explanations. Do not change historical food values merely to make the display appear more plausible.
